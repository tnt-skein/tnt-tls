# tnt-tls

TLS поверх сокета в Tarantool Community Edition: системная OpenSSL
берётся через FFI, а ожидание готовности дескриптора файберное —
соединение, которое ждёт сервер, не останавливает узел. Сертификат
проверяется по умолчанию, имя узла сверяет сама OpenSSL.

```lua
local tls = require('tnt.tls')

local link, err = tls.connect({ host = 'smtp.example.org', port = 465 })
local greeting = link:read({ delimiter = '\r\n' })   -- '220 smtp.example.org ESMTP\r\n'
link:close()
```

Зависимости: `tnt-clock` (часы срока), `tnt-env` (путь к библиотеке
из окружения и `.env`) и `tnt-external` (подмена слоя OpenSSL, сети
и часов в проверках). На машине нужна OpenSSL: `libssl.so.3` либо
`libssl.so.1.1` на Linux, `openssl@3` из Homebrew на macOS.

## Зачем

В Community Edition прикладному коду шифровать нечем: модуля `ssl` там
нет, и всё, что ходит по TCP из Lua, — почта по SMTP, IMAP и POP3,
запросы к чужим службам — уходит открытым текстом вместе с паролями.
Пакет делает четыре вещи:

- **Шифрует тем, что в Community Edition есть** — системной OpenSSL
  через `ffi.load`; где её искать, знает для Linux и macOS, путь можно
  назвать переменной `TNT_TLS_LIBSSL`.
- **Не останавливает узел.** Блокирующий `SSL_read` остановил бы
  не файбер, а весь узел; здесь ожидание снимает файбер с потока через
  `socket:readable` и `socket:writable`, а срок назначается на каждую
  операцию.
- **Строг по умолчанию.** Проверка сертификата выключается только
  словом `false`, имя узла сверяет OpenSSL во время рукопожатия, SNI
  шлётся, ниже TLS 1.2 соединение не опускается.
- **Ведёт себя как сокет.** Чтение по разделителю и по размеру отдаёт
  то же, что `socket:read`, и построчный протокол работает поверх TLS
  без правок.

## Установка

```sh
tt rocks install tnt-tls --server=https://tnt-skein.github.io/rocks
```

Или из исходников:

```sh
git clone https://github.com/tnt-skein/tnt-tls.git
cd tnt-tls && tt rocks make
```

## Как пользоваться

| Вызов | Что делает |
|---|---|
| `tls.available()` | `true` либо `false, err`: есть ли на машине OpenSSL |
| `tls.connect(opts)` | открывает сокет и сразу поднимает TLS (порты 465, 993, 995) |
| `tls.wrap(socket, opts)` | поднимает TLS поверх открытого сокета — STARTTLS |
| `link:read(opts, timeout)` | `{ delimiter = '\r\n' }`, `{ chunk = N }` либо `N`; конец потока — хвост, затем `''` |
| `link:write(text, timeout)` | пишет строку целиком: `true` либо `false, err` |
| `link:close()` | прощается, освобождает OpenSSL и закрывает сокет |
| `link:idle()` | свободно ли соединение: ничего не пришло и оно не закрыто — без сети и без уступки |
| `link:peer()` | `host`, `port`, `protocol`, `cipher` |

Опции: `host` (обязательна), `port` (у `connect` обязателен), `timeout`
(5 с на операцию), `verify` (по умолчанию да), `ca_file` и `ca_path`
(свои корни вместо системных), `sni` (по умолчанию `host`), `cert_file`
и `key_file` (сертификат клиента серверу, который его спрашивает; ключ
без пароля, по умолчанию из файла сертификата).

```lua
-- STARTTLS: разговор начат открытым текстом, сервер согласился
plain:write('STARTTLS\r\n')
plain:read('\r\n')                         -- '220 2.0.0 Ready to start TLS\r\n'

local link, err = tls.wrap(plain, { host = 'smtp.example.org' })

if link == nil then
    plain:close()                          -- при отказе сокет остаётся вызывающему
    return nil, err
end
```

Отказ — пара `nil, err` (у `write` — `false, err`) с текстом, который
называет причину: «соединение с 127.0.0.1:1 не открылось: Connection
refused», «рукопожатие TLS не удалось: сертификат не принят:
self-signed certificate; …», «smtp.example.org не ответил за 5 с».
Непринятый сертификат сервера `connect` и `wrap` называют ещё и словом
третьим значением — `tls.UNTRUSTED` (`'untrusted'`): время такой отказ
не лечит, и тот, кто повторяет соединение, по этому слову отказывает
сразу.

## Проверки

```sh
make deps          # luatest, luacheck, luacov с cluacov и зависимости пакета в .rocks
make check         # форматирование, линт, проверки, покрытие с порогом 100 %
make mutants-all   # мутационное тестирование утилитой tnt-mutants из PATH, порог 100 % убитых
```

Покрытие строк — 100 %, убитых мутантов — 100 % (192 проверки,
492 мутанта в семи модулях). Поведение соединения проверяется
на двойниках сокета и слоя OpenSSL, ветки слоя FFI — на двойнике самой
библиотеки, а живая проверка поднимает `openssl s_server`
с самоподписанным сертификатом и сервер, требующий сертификат клиента;
без `openssl` в системе она пропускается.
