# Шифрование сокета

`tnt-tls` поднимает TLS поверх сокета Tarantool Community Edition:
системная OpenSSL берётся через FFI, а ожидание готовности дескриптора
файберное — соединение, которое ждёт сервер, не останавливает узел.

```lua
local tls = require('tnt.tls')

local link, err = tls.connect({ host = 'smtp.example.org', port = 465 })
local greeting = link:read({ delimiter = '\r\n' })   -- '220 smtp.example.org ESMTP\r\n'
link:close()
```

Сертификат проверяется по умолчанию, имя узла сверяет сама OpenSSL,
ниже TLS 1.2 соединение не опускается; серверу, который спрашивает
сертификат клиента, его можно предъявить. Отказ — пара `nil, err`;
непринятый сертификат сервера назван ещё и словом `untrusted`.

## Зачем пакет

В Community Edition прикладному коду шифровать нечем: модуля `ssl` там
нет, а шифрование iproto доступно только ядру Enterprise Edition. Всё,
что ходит по TCP из Lua, — почта по SMTP, IMAP и POP3, запросы к чужим
службам — уходит открытым текстом, и пароль учётной записи в открытом
SMTP видит всякий, кто видит сеть. Пакет делает четыре вещи:

- **Шифрует тем, что в Community Edition есть.** Tarantool собран
  с OpenSSL, но её символы прикладному коду не отданы, поэтому
  библиотека берётся у системы через `ffi.load` — своим экземпляром,
  рядом с тем, которым пользуется ядро. Где её искать, пакет знает
  для Linux и macOS, а путь можно назвать и самому.
- **Не останавливает узел.** OpenSSL на неблокирующем сокете отвечает
  не «ошибка», а «повтори, когда дескриптор будет готов». Крутить
  на этом цикл — занять поток целиком; перевести сокет в блокирующий
  режим — значит, что `SSL_read` остановит не файбер, а весь узел,
  вместе с репликацией, откликом на iproto и пробами живости. Здесь
  ожидание снимает файбер с потока: `socket:readable`
  и `socket:writable` возвращают его, когда ядро говорит о готовности.
- **Строг по умолчанию.** Проверка сертификата включена, пока её
  не выключили словом `false`; имя узла сверяет OpenSSL во время
  рукопожатия; имя для SNI шлётся; TLS 1.0 и 1.1 не предлагаются.
- **Ведёт себя как сокет.** Чтение по разделителю и по размеру отдаёт
  то же, что `socket:read`, поэтому построчный протокол, написанный
  под сокет, работает поверх TLS без правок.

Зависимости: `tnt-clock` (часы срока), `tnt-env` (путь к библиотеке
из окружения и `.env`) и `tnt-external` (подмена слоя OpenSSL, сети
и часов в проверках). Настроек у пакета нет — ни `configure`, ни `new`:
всё, что нужно соединению, приходит опциями вызова.

## Как пользоваться

```lua
local tls = require('tnt.tls')
```

| Вызов | Что делает |
|---|---|
| `tls.available()` | `true` либо `false, err`: есть ли на машине OpenSSL |
| `tls.connect(opts)` | открывает сокет и сразу поднимает TLS; соединение либо `nil, err, kind` |
| `tls.wrap(socket, opts)` | поднимает TLS поверх открытого сокета — так работает STARTTLS; соединение либо `nil, err, kind` |
| `tls.UNTRUSTED` | `'untrusted'` — `kind` отказа, когда не принят сертификат сервера |
| `link:read(opts, timeout)` | кусок по разделителю либо по размеру; `nil, err` |
| `link:write(text, timeout)` | пишет строку целиком: `true` либо `false, err` |
| `link:close()` | прощается, освобождает OpenSSL и закрывает сокет |
| `link:idle()` | свободно ли соединение: ничего не пришло и оно не закрыто — без сети и без уступки |
| `link:peer()` | узел, порт, договорённые шифр и версия протокола |

### Есть ли чем шифровать: `available`

```lua
local ok, why = tls.available()

if not ok then
    log.error('TLS недоступен: %s', why)
end
```

Спрашивать стоит при настройке, а не посреди отправки письма: «TLS
недоступен» в начале — это настройка, а в середине — потерянное письмо.
Причина перечисляет, где библиотеку искали:

```
OpenSSL не нашлась: не загрузилась ни одна из библиотек (libssl.so.3, libssl.so.1.1, libssl.so). Поставьте её (brew install openssl@3 либо пакет libssl3) или укажите путь переменной окружения TNT_TLS_LIBSSL
```

### Шифрование с первого байта: `connect`

На портах 465 у SMTP, 993 у IMAP и 995 у POP3 шифрование начинается
с первого байта: `connect` открывает сокет и сразу поднимает TLS.

```lua
local link, err = tls.connect({ host = 'smtp.example.org', port = 465, timeout = 10 })

if link == nil then
    return nil, err
end

link:read({ delimiter = '\r\n' })          -- '220 smtp.example.org ESMTP\r\n'
link:write('EHLO node.example.org\r\n')
link:read({ delimiter = '\r\n' })          -- '250 smtp.example.org\r\n'
link:write('QUIT\r\n')
link:read({ delimiter = '\r\n' })          -- '221 2.0.0 Bye\r\n'
link:close()
```

Опции проверяются до того, как открыт сокет. Отказ сети называет
причину, которую дала сеть, а без причины — срок:

```lua
tls.connect({ host = '127.0.0.1', port = 1 })
--> nil, 'соединение с 127.0.0.1:1 не открылось: Connection refused'
```

Если рукопожатие сорвалось, `connect` закрывает сокет, который открыл
сам.

### STARTTLS: `wrap`

В STARTTLS разговор начинается открытым текстом, клиент просит сервер
перейти на шифрование, и дальше по тому же сокету идёт TLS. Сокет
открывает вызывающий, `wrap` поднимает TLS поверх него:

```lua
local socket = require('socket')

local plain = socket.tcp_connect('smtp.example.org', 587, 5)

plain:read('\r\n')                         -- '220 smtp.example.org ESMTP\r\n'
plain:write('EHLO node.example.org\r\n')

-- Ответ на EHLO — несколько строк, последняя без дефиса: '250 STARTTLS\r\n'.
repeat
    local line = plain:read('\r\n')
until line == nil or line:sub(4, 4) ~= '-'

plain:write('STARTTLS\r\n')
plain:read('\r\n')                         -- '220 2.0.0 Ready to start TLS\r\n'

local link, err = tls.wrap(plain, { host = 'smtp.example.org' })

if link == nil then
    plain:close()                          -- при отказе сокет остаётся вызывающему
    return nil, err
end

link:write('EHLO node.example.org\r\n')    -- после STARTTLS здороваются заново
```

Имя узла обязательно и здесь: сертификат проверяется по нему, а сокет
своего имени не помнит — только адрес. Порт не нужен: `peer()` спросит
его у сокета. При отказе `wrap` освобождает то, что завёл сам, а сокет
оставляет вызывающему; после удачного `wrap` сокет закрывает
`link:close()`.

### Опции

| Опция | Что значит | Если не задана |
|---|---|---|
| `host` | имя узла; по нему же проверяется сертификат | отказ |
| `port` | порт, целое от 1 до 65535 | у `connect` отказ, у `wrap` не нужен |
| `timeout` | срок одной операции в секундах, больше нуля | 5 |
| `verify` | проверять ли сертификат; выключает только `false` | проверять |
| `ca_file` | файл доверенных корней вместо системных | системные корни |
| `ca_path` | каталог доверенных корней вместо системных | системные корни |
| `sni` | имя для SNI; пустая строка и числовой адрес — не слать | `host` |
| `cert_file` | сертификат клиента PEM, за ним — промежуточные | не предъявлять |
| `key_file` | ключ клиента PEM без пароля; без `cert_file` — отказ | из `cert_file` |

Негодная опция — отказ до сокета:

```lua
tls.connect({ host = 'smtp.example.org' })
--> nil, 'порт должен быть числом от 1 до 65535, а не nil'
tls.connect({ host = 'smtp.example.org', port = 465, timeout = 0 })
--> nil, 'срок ожидания должен быть положительным числом, а не 0'
tls.connect({ host = 'smtp.example.org', port = 465, ca_file = 123 })
--> nil, 'ca_file должен быть строкой, а не number'
tls.connect({ host = 'smtp.example.org', port = 465, key_file = '/etc/ssl/client.key' })
--> nil, 'key_file без cert_file: ключ предъявляется только вместе с сертификатом'
tls.wrap(plain, {})
--> nil, 'не сказано, с каким узлом соединяться: нет host'
```

Срок — на операцию, а не на соединение: столько ждёт рукопожатие,
столько же — каждое чтение и каждая запись, которым не дали свой.
Построчный протокол ждёт ответа на каждую команду, и общий срок
на соединение кончился бы посреди разговора.

### Чтение: `read`

```lua
link:read({ delimiter = '\r\n' })                -- до разделителя включительно
link:read({ chunk = 512 })                       -- ровно 512 байт
link:read(512)                                   -- то же
link:read({ delimiter = '\r\n', chunk = 1000 })  -- до разделителя, но не длиннее 1000 байт
link:read({ delimiter = '\r\n' }, 30)            -- свой срок вместо timeout соединения
```

Шифрованный поток приходит кусками, которые не совпадают ни со
строками протокола, ни с запрошенным размером: одно чтение приносит
три ответа сервера сразу или полстроки. Прочитанное копится, а выдаётся
ровно столько, сколько просили, — как у `socket:read`. Разделитель
отдаётся вместе с куском. Размер считается в байтах.

Чтение по разделителю копит не больше мегабайта: сервер, у которого
строки не кончаются, иначе съел бы память узла. Свой предел — `limit`:

```lua
link:read({ delimiter = '\r\n', limit = 64 * 1024 })
--> nil, 'строка длиннее 65536 байт: разделитель так и не пришёл'
```

Конец потока — не отказ. Когда другая сторона закончила, чтение отдаёт
накопленный хвост, даже короче запрошенного и без разделителя,
а следующее — пустую строку. Так «сервер закончил» отличается
от «сервер молчит», и тело, которое идёт до конца потока, читается
циклом:

```lua
local parts = {}

while true do
    local piece, err = link:read({ chunk = 4096 })

    if piece == nil then
        return nil, err
    end

    if piece == '' then
        break
    end

    table.insert(parts, piece)
end

local body = table.concat(parts)
```

Отказы чтения: `'<host> не ответил за <срок> с'`, `'соединение закрыто'`
после `close`, `'не сказано, сколько читать: …'` на негодном запросе
и `'чтение из TLS не удалось: …'` с разбором OpenSSL.

### Запись: `write`

```lua
local ok, err = link:write('MAIL FROM:<robot@example.org>\r\n')

if not ok then
    return nil, err
end
```

Строка уходит целиком, а не сколько получится: половина команды
протокола — это сорванный разговор, а не частичный успех. Вторым
аргументом — свой срок. Пустая строка отвечает `true`, до OpenSSL
не доходя: запись нулевой длины у неё не определена.

Отказы записи: `'<host> не принял запись за <срок> с'`, `'<host> закрыл
соединение посреди записи'`, `'писать можно строку, а не table'`,
`'соединение закрыто'` и `'запись в TLS не удалась: …'`.

### Закрытие: `close`

`close` прощается в обе стороны: шлёт своё `close_notify` и ждёт чужое —
не дольше секунды и не дольше срока соединения. Затем освобождает `SSL`
и `SSL_CTX` и закрывает сокет — и открытый `connect`, и отданный в `wrap`:
после освобождения сессии он не годится ни на что. Повторный `close`
ничего не делает; чтение и запись после него отвечают
`'соединение закрыто'`.

Прощание не держит файбер: сервер вправе закрыть сокет сразу после
своего `close_notify`, и повисший на чужом прощании файбер был бы
хуже невежливости.

### Свободно ли соединение: `idle`

```lua
if not link:idle() then
    link:close()          -- сервер закрыл его в простое либо прислал лишнее
end
```

`idle()` отвечает `true`, если соединение цело и в нём ничего нет:
ни данных, ни прощания, ни конца потока. Без сети и без уступки — это
вопрос пулу перед выдачей соединения, и ответ нужен сразу. Свободному
соединению сервер обычно не шлёт ничего, а закрыв его, шлёт прощание
TLS и конец потока. Смотрится в три места: в прочитанное, но ещё
не отданное, в OpenSSL — там лежат записи, уже взятые из сокета, —
и в сам сокет. Сокет не читается, а только заглядывается (`MSG_PEEK`):
прочитанную запись TLS в поток не вернуть, и соединение, признанное
свободным, после такой проверки было бы испорчено.

Ответ строже, чем нужно: служебная запись, которую сервер вправе
прислать и живому соединению (смена ключей), тоже отвечает `false`.
Билеты сессии TLS 1.3 приходят сразу за рукопожатием и снимаются первым
же чтением ответа, поэтому соединение, прочитавшее хоть один ответ,
свободно. После `close()` — `false`.

### С кем и чем: `peer`

```lua
link:peer()
--> { host = 'smtp.example.org', port = 465, protocol = 'TLSv1.3', cipher = 'TLS_AES_256_GCM_SHA384' }
```

Для журнала и разбора: без шифра и версии в записи «соединился» нельзя
ни отличить TLS 1.2 от 1.3, ни заметить, что сервер сговорился на слабый
шифр. Шифр и версия снимаются сразу после рукопожатия, поэтому `peer()`
отвечает и после `close`. Порт после `wrap` спрашивается у сокета;
не сказал — `port` пуст.

### Проверка сертификата

Включена по умолчанию, и выключить её можно только словом `false`:

```lua
tls.connect({ host = 'smtp.internal', port = 465, verify = false })   -- осознанный выбор
```

Всякое другое значение, включая строку `'false'` из конфигурации,
оставляет проверку включённой: ошибиться в сторону строгости здесь
безопасно, в другую — нет.

Шифрование без проверки защищает от подслушивания, но не от подмены: тот,
кто может читать трафик, обычно может и встать посередине, и тогда
шифрованный канал ведёт к нему. Против сервера с самоподписанным
сертификатом в своём же контуре лучше дать свой корень — файлом либо
каталогом, приготовленным `openssl rehash`:

```lua
tls.connect({ host = 'smtp.internal', port = 465, ca_file = '/etc/ssl/own-root.pem' })
tls.connect({ host = 'smtp.internal', port = 465, ca_path = '/etc/ssl/own-roots' })
```

Названные корни заменяют системные, а не добавляются к ним: тот, кто
назвал свой удостоверяющий центр, обычно и хочет, чтобы никакой другой
не подошёл.

Имя узла сверяет сама OpenSSL во время рукопожатия, а не пакет после
него: проверка, сделанная своими руками потом, однажды окажется
пропущенной — шифрование к тому времени уже работает, и пропуск ничем
себя не выдаёт. Отказ проверки называет, что именно не сошлось:

```
рукопожатие TLS не удалось: сертификат не принят: self-signed certificate; error:0A000086:SSL routines::certificate verify failed
```

### Непринятый сертификат — словом

Такой отказ `connect` и `wrap` называют ещё и словом третьим значением —
`tls.UNTRUSTED`, строкой `'untrusted'`:

```lua
local link, err, kind = tls.connect({ host = 'localhost', port = 6380 })
--> nil, 'рукопожатие TLS не удалось: сертификат не принят: self-signed certificate in certificate chain; …', 'untrusted'

if kind == tls.UNTRUSTED then
    return nil, err                        -- настройка, а не беда сети: повторять незачем
end
```

Сеть, моргнувшая на полсекунды, поднимется сама, а сертификат, выписанный
не тем корнем или не на то имя, останется таким, сколько ни повторяй.
Кто повторяет соединение до конца срока, по этому слову отказывает сразу
и не выдаёт настройку за беду сети. Слово — а не сверка с текстом: текст
причины меняется вместе с OpenSSL, и сверка однажды перестала бы узнавать
отказ, ничем себя не выдав.

Слово ставит только проверка сертификата сервера. У остальных отказов —
сеть, срок, негодная опция, нечитаемый файл, сервер, не принявший наш
сертификат, — третьего значения нет, как нет его и при `verify = false`.

Для числового адреса в `host` имя для SNI не шлётся — RFC 6066 это
запрещает, и некоторые серверы обрывают рукопожатие, — а сертификат
OpenSSL 3 сверяет с адресом, и выписан он должен быть на адрес:
`subjectAltName=IP:…`. Опция `sni` меняет только имя, которое уходит
серверу в рукопожатии; сертификат всё равно сверяется с `host`.

### Сертификат клиента

Сервер, который пускает только своих, спрашивает сертификат клиента
в рукопожатии: так делают Redis с `tls-auth-clients yes` (его умолчание),
брокеры и базы со взаимной проверкой. Сертификат и ключ называются
файлами PEM:

```lua
tls.connect({
    host = 'cache.internal',
    port = 6380,
    ca_file = '/etc/ssl/own-root.pem',
    cert_file = '/etc/ssl/client.pem',
    key_file = '/etc/ssl/client.key',
})
```

Сертификат читается с цепочкой: промежуточные сертификаты кладут в тот
же файл за ним, и они уходят серверу вместе с ним. Ключ, лежащий в том
же файле, называть не нужно: без `key_file` он ищется в `cert_file`.
Ключ без сертификата — отказ до сокета. Сертификат клиента не зависит
от проверки сервера и предъявляется и при `verify = false`.

Файлы читаются при каждом соединении, как и доверенные корни: сертификат,
заменённый на диске, берёт следующее же соединение, без перезапуска
узла. Ключ сверяется с сертификатом до рукопожатия: ключ другого рода
(EC при сертификате RSA) OpenSSL принимает молча, и без сверки отказ
пришёл бы от сервера, ни словом не назвав ключ. Отказы называют файл:

```
чтение сертификата клиента /etc/ssl/nobody.pem не удалось: error:80000002:system library::No such file or directory; error:10080002:BIO routines::system lib; error:0A080002:SSL routines::system lib
чтение ключа клиента /etc/ssl/locked.key не удалось: error:1C800064:Provider routines::bad decrypt; …; error:0A080009:SSL routines::PEM lib
сопоставление ключа /etc/ssl/stranger.key с сертификатом /etc/ssl/client.pem не удалось: error:0A0000B1:SSL routines::no certificate assigned
```

Ключ — без пароля. Ключ под паролем OpenSSL стала бы расшифровывать
паролем, спрошенным у терминала, и узел, запущенный из терминала, встал бы
в ожидании ответа. Поэтому пароль всегда пустой, и ключ под паролем —
отказ сразу (второй из примеров выше); снять пароль —
`openssl pkey -in locked.key -out client.key`.

Сервер, которому сертификат не предъявили или он не подошёл, отказывает.
В TLS 1.3 он судит о сертификате клиента, когда рукопожатие у клиента
уже кончилось, поэтому `connect` удаётся, а отказ приходит первым
чтением:

```lua
local link = tls.connect({ host = 'cache.internal', port = 6380, ca_file = '/etc/ssl/own-root.pem' })

link:write('PING\r\n')
link:read({ delimiter = '\r\n' })
--> nil, 'чтение из TLS не удалось: error:0A00045C:SSL routines::tlsv13 alert certificate required'
```

Разбор проверки сертификата сервера идёт в текст отказа, только когда
проверка включена: без неё OpenSSL всё равно пишет вердикт, но отказа
он не вызывал, и «сертификат не принят: self-signed certificate» увёл бы
разбор от нашего сертификата к серверному.

### Где ищется OpenSSL

Библиотека пробуется по списку, и берётся первая, которая загрузилась:

- Linux и прочие системы: `libssl.so.3`, `libssl.so.1.1`, `libssl.so`.
  Имя с версией идёт раньше: `libssl.so` — ссылка из пакета
  для разработки, и на рабочем узле её обычно нет.
- macOS: каталоги Homebrew `openssl@3` и `openssl@1.1` для Apple Silicon
  (`/opt/homebrew/opt/…`) и Intel (`/usr/local/opt/…`), затем
  `libssl.3.dylib` и `libssl.1.1.dylib`. Системная
  `/usr/lib/libssl.dylib` не пробуется: на macOS это LibreSSL другой
  породы.

Библиотеку, лежащую не на привычном месте, называют переменной
`TNT_TLS_LIBSSL`:

```sh
TNT_TLS_LIBSSL=/opt/openssl-3.5/lib/libssl.so.3 tarantool app.lua
```

Путь пробуется первым, но остальных мест не отменяет: опечатка в нём
не должна лишать узел шифрования. Переменную читает `tnt-env`, так что
годится и строка в `.env`. Загруженная библиотека одна на процесс.

Ту же библиотеку берёт проверка подписи открытым ключом
[`tnt-crypto`](https://github.com/tnt-skein/tnt-crypto/blob/main/docs/crypto.md)
(раздел «Проверка подписи»): функции libcrypto она зовёт через ручку
libssl, и переменная `TNT_TLS_LIBSSL` действует и на неё.

### Подмена в проверках

Внешние зависимости пакета подменяются `_set_source` (`tnt-external`)
в трёх модулях:

| Модуль | Внешние зависимости |
|---|---|
| `tnt.tls` | `connect(host, port, timeout)` — открытие сокета; `backend()` — слой OpenSSL |
| `tnt.tls.link` | `monotonic`, `scheduler_now` — часы срока |
| `tnt.tls.openssl` | `open(name)` — загрузка библиотеки; `system` — род системы строкой, как `jit.os`; `getenv(name)` — чтение окружения |

Проверка кода, который ходит через `tnt-tls`, обычно подменяет сеть
и слой OpenSSL. Слой отвечает не кодами OpenSSL, а состояниями
`tnt.tls.outcome`: `done`, `want_read`, `want_write`, `closed`, `failed`.
Отказ рукопожатия `failed` третьим значением может назвать род —
`'untrusted'`, и `connect` с `wrap` отдают его вызывающему:
`handshake = function() return 'failed', 'сертификат не принят', 'untrusted' end`.
Двойник на весь разговор — сокет с дескриптором и ожиданиями готовности
и слой, отвечающий по листу:

```lua
local tls = require('tnt.tls')

local socket = {
    fd = function() return 7 end,
    readable = function() return true end,
    writable = function() return true end,
    peer = function() return { host = '10.0.0.7', port = 465 } end,
    close = function() end,
}

local layer = {
    library = function() return {} end,
    open = function(fd, settings) return { fd = fd } end,
    handshake = function(session) return 'done' end,
    read = function(session) return 'done', '220 smtp.example.org ESMTP\r\n' end,
    write = function(session, text, sent) return 'done', #text - sent end,
    shutdown = function(session) return 'done' end,
    release = function(session) end,
    describe = function(session) return { protocol = 'TLSv1.3', cipher = 'TLS_AES_128_GCM_SHA256' } end,
    buffered = function(session) return false end,
}

tls._set_source({
    connect = function() return socket end,
    backend = function() return layer end,
})

local link = tls.connect({ host = 'smtp.example.org', port = 465 })
t.assert_equals(link:read({ delimiter = '\r\n' }), '220 smtp.example.org ESMTP\r\n')

tls._set_source(nil)
```

`buffered` отвечает, не осталось ли в OpenSSL непрочитанного, — его
спрашивает `link:idle()`. Двойнику сокета для `idle()` нужны ещё
`recv(size, flags)` и `errno()`: в сокет при этом заглядывают.

Загруженную библиотеку и вердикт «её нет» `tnt.tls.openssl` помнит
на весь процесс; `forget()` забывает их — без этого вызова подмена
`open` после первой загрузки до библиотеки не дойдёт.

## Чем пришлось поступиться

- **Обрыв TCP без прощания считается концом данных, а не отказом.**
  Так заканчивают разговор почти все почтовые серверы, и строгость
  превратила бы каждую удачную отправку в отказ. Плата: обрезание потока
  посередине выглядит как «сервер закончил». Защита остаётся
  на протоколе выше — тот, кто ждал подтверждения и не получил его,
  обязан считать отправку неудавшейся.
- **`SSL_CTX` заводится свой на каждое соединение.** Общий стоил бы
  дешевле — доверенные корни читаются при его настройке, — но означал
  бы состояние, общее для всех: настройки одного вызывающего доставались
  бы другому, а опечатка в корнях отравляла бы весь узел до перезапуска.
  Плата — чтение хранилища корней на каждое соединение: миллисекунды.
  Для почты незаметно, для тысяч соединений в секунду — нет.
- **`link:close()` закрывает и сам сокет**, в том числе после `wrap`.
  А вот при неудачном рукопожатии в `wrap` сокет остаётся вызывающему:
  закрыть чужой сокет за него — значит однажды закрыть тот, который ему
  ещё нужен.
- **Вердикт «библиотеки нет» запоминается на век процесса.** Поиск
  по списку не повторяется на каждом соединении, и поставить OpenSSL
  без перезапуска узла не поможет.
- **Путь к `libssl` пакет читает из окружения сам**, а не принимает
  аргументом: библиотека одна на процесс и грузится при первом
  шифровании, и настраивать её у каждого вызывающего было бы обещанием,
  которое нельзя сдержать. Читает через `tnt-env`, поэтому негодный
  `.env` бросает из первого `available()` или `connect`, если
  приложение не прочитало окружение раньше. Приложение, которое читает
  окружение при старте, узнаёт о негодном файле там.
- **Срок — на операцию, а не на разговор.** Разговор из десяти команд
  может идти десять сроков; кому нужен общий предел, тот считает его
  сам и отдаёт остаток вторым аргументом `read` и `write`.
- **Только клиент.** Принимать TLS пакет не умеет. Нижняя граница —
  TLS 1.2, и она не настраивается.
- **Ключ клиента — только без пароля.** Пароль к ключу пришлось бы
  держать в настройках рядом с путём к ключу, а без пароля OpenSSL
  спросила бы его у терминала и остановила узел. Пароль всегда пустой,
  и ключ под паролем — отказ при соединении.
- **`idle()` строже, чем нужно.** Служебная запись, которую сервер
  вправе прислать и живому соединению, тоже отвечает «не свободно».
  Цена ошибки в эту сторону — лишнее соединение, в другую — отказ
  на запросе, который уже ушёл.

## Проверки

Проверки лежат в `test/` и идут на luatest: `.rocks/bin/luatest test/`.
Двойников три, и они разного уровня. Двойник сокета отвечает
на ожидания готовности и записывает, сколько соединение соглашалось
ждать. Двойник слоя FFI отвечает состояниями по листу — на нём
проверяется всё поведение соединения без OpenSSL: сроки на подменённых
часах, ожидание вместо цикла, накопление, отказ посреди записи,
прощание в пределах оборотов и срока. Двойник самой OpenSSL отвечает
указателями и заполненными буферами — на нём проверяются ветки слоя
FFI, которых на исправной машине не добиться: пустой `SSL_CTX_new`,
непрочитанные корни, очередь ошибок.

Живая проверка `tls_live_test.lua` поднимает `openssl s_server`
с самоподписанным сертификатом во временном каталоге и проверяет
настоящее рукопожатие, отказ самоподписанного сертификата и чужого
имени со словом `untrusted`, свой корень, срок чтения, соседний файбер,
который работает, пока соединение ждёт, и сто соединений подряд без
роста памяти. Третий сервер требует сертификат клиента (`-Verify`):
с сертификатом он пускает, с сертификатом и ключом в одном файле — тоже,
без сертификата — нет, и слова `untrusted` у этого отказа нет; ключ
другого рода, ключ под паролем и несуществующий файл отказывают
до рукопожатия. Там же `idle()`: соединение, прочитавшее
ответ, свободно, закрытое сервером — нет, а пришедший ответ заглядывание
не портит. Без `openssl` в системе или без библиотеки она пропускается
и говорит, чего не хватает. Покрытие строк — 100 %, убитых мутантов —
100 %.
